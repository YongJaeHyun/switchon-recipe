# 조리 순서 가독성 + 요리 모드

운영자 결정 2026-11-04. 시안: `.superpowers/brainstorm/79057-1793694908/content/cooking-mode.html`

## 왜
레시피를 보고 실제로 요리하며 따라 할 때 조리 순서가 읽기 어렵다(핵심 기능). 한 단계가 2~3문장 문단이고 손질·불 세기·양·시간·주의사항이 한 덩어리, 모두 같은 크기·굵기.

## 정한 것
### ① 상세 화면(app/recipeDetail.tsx)의 조리 순서
- 단계마다 문장을 동작별 줄(점 목록)로 나눈다. 한 문장뿐이면 그대로 한 줄.
- 양(숫자+단위: 200ml, 1/2큰술, 1스쿱, 2개, 150g …)은 초록 강조, 불 세기·시간(약불, 중간 불, 센 불, 5분, 30초, 한소끔)은 주황 강조.
- 괄호 속 설명 `( … )`은 본문에서 빼서 단계 아래 회색 팁 상자 "💡 …"로.
- 단계를 누르면 끝낸 것으로 흐리게+취소선 (다시 누르면 되돌림). 기억은 이 레시피를 보는 동안만(화면 상태). 서버에 안 보냄.
- 시간이 든 단계에는 [⏱ N분 타이머] 칩 → 요리 모드의 타이머와 같은 동작(아래).
- 제목 줄 옆 "약 N분 · M단계", 그 아래 [▶ 요리 시작] 버튼.

### ② 요리 모드 (새 전체 화면 라우트, 예: app/cookingMode.tsx — 레시피는 recipeDetail처럼 파라미터로)
- 한 단계만 큰 글씨(약 21~22pt, 굵게), 위와 같은 강조·팁 상자. 어두운 바탕(시안).
- 위: ✕ 닫기 · 레시피 이름 · "5 / 7", 진행 막대. [재료 보기]는 재료 목록 시트(인분 조절 반영된 양)를 연다.
- 아래: 큰 [← 이전] / [다음 단계 →], 마지막 단계에서는 [완성!] (닫기). 좌우로 밀어도 넘어간다.
- 요리하는 동안 화면이 꺼지지 않는다 (`expo-keep-awake` — expo에 이미 포함돼 있음. 스토어 빌드에 네이티브가 들어 있는지 확인하고, 없으면 OTA로는 동작하지 않으니 보고).
- 타이머: 단계에 시간이 있으면 그 단계 화면에 타이머 카드 (시작/일시정지/다시). 여러 개가 동시에 돌 수 있고, 다른 단계로 넘어가도 계속 돈다(위쪽에 작은 타이머 줄). 끝나면 진동(RN Vibration) + 로컬 알림(expo-notifications, 이미 사용 중) — 앱이 백그라운드여도 알림이 온다. 요리 모드를 닫으면 남은 타이머 알림 취소.
- 마지막으로 본 단계는 같은 레시피를 다시 열면 이어서 (이번 실행 동안만).

### ③ 새로 만드는 레시피 문장 (서버 _shared/recipeText.ts 생성 프롬프트)
- cookingSteps 형식은 그대로 string[] (옛 앱 호환). 각 단계는 짧은 문장 1~3개, 문장마다 동작 하나, 양·불 세기·시간을 숫자로, 주의사항은 단계 끝 괄호 한 개에만. "~합니다"보다 "~해요"체. 
- 기존 레시피는 바꾸지 않는다 (앱의 ①② 처리로 충분).

## 빌더 판단
- 문장 나누기·강조·팁 분리는 순수 함수(utils/cookingSteps.ts)로, vitest 먼저. 실제 레시피 문장 예시 여러 개로 테스트 (소수·분수·범위 "1~2큰술", "약 5분", "5~7분", 괄호 여러 개, 괄호 안 문장부호, 마침표 없는 문장, "(또는 육수)"처럼 짧은 대안 괄호는 팁으로 빼지 말고 본문에 남기기 — 길이·내용으로 판단 기준 정하기).
- 타이머 시간 추출: 단계의 시간 표현 중 하나(가장 긴 것? 첫 번째?)를 정하고 테스트로 고정. 범위면 큰 쪽.
- UI는 frontend-design 스킬, 기존 디자인 언어(초록, Pretendard). 요리 모드만 어두운 바탕.
- 접근성: 큰 버튼 터치 영역, 스크린리더 라벨.

## 하지 않는 것
- 음성 읽기·음성 명령, 단계 사진, 서버에 진행 상황 저장.

## 지킬 것
- 문구 쉬운 한국어, "회차" 금지. 레시피 문장 내용 자체(책 기준 재료·양)는 바꾸지 않는다 — 나누기·강조만.
- 에뮬레이터는 운영자 실계정: 저장·만들기 금지(보기만). 기존 레시피를 열어 확인.
