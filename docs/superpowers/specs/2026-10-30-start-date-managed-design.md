# 시작일은 앱이 관리하기 (날짜 선택 없애기)

작성일: 2026-10-30 · 대상: `feature/premium-features` (6.0.0) · 운영자 결정

## 왜
- 사용자는 날짜가 아니라 "지금 2주차 3일"로 생각하는데, 지금은 달력에서 아무 날짜나 고른다(`components/home/StartDateBottomSheet.tsx`, 온보딩 "네, 하고 있어요" 달력).
- 아무 날짜로나 점프할 수 있어서 시작일에 묶인 것(할 일, 단식, 통계, 주간 리포트, 체중 그래프 색, 패스 기간 표시, 한 주 더 키, 끼니·아침 알림, 준비 체크)마다 예외 처리가 계속 붙는다.
- 목표: 앱 어디에서도 사용자가 날짜를 직접 고르지 않는다. 시작일은 앱이 계산한다.

## 사용자가 할 수 있는 것 (두 가지만)
1. **처음부터 다시 시작** — [내일부터 시작 (추천)] / [오늘부터 시작]. 1주차 1일로 새로 시작.
   - 확인 단계 한 번(되돌릴 수 없는 동작): "지금까지 기록은 이전 차수로 남아요".
   - 실제로 남는 것: 체중·인바디 기록(날짜 기준, 그래프에서 시작일 이전은 이미 회색), 주간 리포트(날짜 범위 기준, 이미 차수별로 묶임). 남지 않는 것: 할 일 완료율 통계(`statistics`는 주차·일차 키라 새 차수가 덮어씀) — 지금도 시작일 변경 시 지우므로 동작 동일. 문구는 사실대로("체중 기록과 리포트는 남아요").
2. **주차 맞추기** — "지금 몇 주차 며칠인가요?" [1주차][2주차][3주차][4주차][유지기] × [1일]…[7일] 선택 → 시작일 = 오늘 − ((주차−1)×7 + (일−1))일. 유지기는 5주차 1일로 계산.
   - 과거·오늘 시작만 가능(앞으로 당기기 불가) — 미래 시작은 '처음부터 다시 시작 → 내일부터'로만.
   - 지금 주차·일차를 기본 선택으로 보여 준다.
- 두 동작 모두 기존 `StartDateBottomSheet.updateStartDate`가 하던 정리를 그대로 한다(주차보다 높은 선택 재료 제거, `StatisticsAPI.deleteFrom`, 쿼리 무효화). 시작일을 바꾸는 코드는 한 함수로 모은다(온보딩·설정·한 주 더 하기가 같은 함수 사용).

## 온보딩
- "네, 하고 있어요" → 달력 대신 위의 **주차 맞추기** 선택(같은 컴포넌트).
- "이제 시작하려고 해요" → 기존 내일/오늘 선택 그대로. "아니오, 레시피만 볼래요" → 그대로(유지기).

## 바뀌지 않는 것
- 서버·DB 변경 없음. `user.start_date` 그대로 쓰고 앱이 계산해서 넣는다.
- "한 주 더 하기"(시작일 +7)는 그대로, 다만 같은 시작일 변경 함수를 쓴다.

## 화면
- 진입점: 오늘 탭 주차 옆 ⚙, 내 정보의 기존 진입점 → 새 '프로그램 설정' 시트.
- 디자인은 frontend-design 스킬로(운영자 규칙). 앱 디자인 언어(초록, 주차 색 `getWeekColor`) 안에서. 주차 선택 칩은 주차 색을 쓴다.
- 시안은 컨트롤러가 운영자에게 확인받은 ASCII 안 기준:
```
⚙ 프로그램 설정
처음부터 다시 시작하기 → [내일부터 (추천)] [오늘부터]  (확인 단계)
주차가 실제와 달라요   → 지금 [N주차] [N일] 고르기
```
